The first session should make the outcome understandable before asking for input: a strong, labeled example → an obvious way to replace the input → one local change → a reviewable output. An example demonstrates possibility; it does not prove that automation made the creative decisions or that export has passed its checks.

## Shared product rules

- Label example content and keep a visible import action beside it. A newcomer should see both what is possible and where to begin.
- Load lightweight viewing copies and thumbnails. Decode only what the current presentation needs; pause background playback and honor reduced-motion preferences.
- Keep content replacement separate from styling. Protect visitor work before loading a whole example over it; preserve other choices during a local replacement.
- Explain the source of the result: supplied artwork, deterministic layout, local inference, or proposed agent behavior. Never present a sample as a fresh autonomous success.
- Show input, preview and output states. Encoding completion does not certify editorial timing, transcript meaning or target accuracy.
- Test one unfamiliar creator's complete task before adding more presets. Record actual observations; do not fabricate time savings or adoption data.
