# Evidence, decisions and next experiments

[← Seven-project index](../README.md#selected-work) · [Creator control](creative-control.md) · [Validation record](creator-validation.md)

**My working proposition: production experience helps me identify what creators need to control, and AI-assisted implementation lets me turn that judgment into a usable prototype.**

This portfolio connects three kinds of evidence: a commercial asset product, interactive tools, and the decisions behind them. They are at different stages. The assessment below separates what can be inspected today from what still needs a task-based demonstration.

## A short review route

1. **Production judgment → product:** [Clockwork's complete case](https://github.com/MuwenTriLi/steampunk-clockwork-showcase/blob/main/docs/production-case.md). Start with one mechanism, its meaningful controls and the dependencies those controls preserve.
2. **Feedback → product iteration:** [Collage Motion](../projects/03-collage-motion.md#from-prototype-to-a-usable-first-session). The interface was revised after specific feedback about import discovery, timeline access, distorted thumbnails and output review. Try the updated app with your own media.
3. **Direct interaction:** [Model Breakdown Studio](https://meshroom-breakdown-studio.limuwen9.chatgpt.site). Choose Wood House or a production-line example to inspect a part, compare assembled and exploded views, and adjust the presentation.

The other projects explore different problems. They do not need to appear equally finished to be useful evidence of product judgment.

## What this body of work demonstrates—and what remains open

| Capability | Current support | Next evidence that would strengthen it |
| --- | --- | --- |
| Understand production from the inside | Clockwork's motion dependencies; architecture's continuity criteria; media tools' framing, timing and legibility decisions | A short practitioner account showing the original production constraint and a real revision |
| Turn an idea into an interactive prototype with AI and code | Working browser interfaces; Collage source and tested export; the local Model Breakdown implementation | A reproducible brief → code/interaction decision → output record, with the creator's role explicit |
| Define what the agent may do | Per-project automatic work, protected decisions and proposed review boundaries | A fresh agent execution with tool inputs, changed settings, interruption/correction and output checks |
| Deliver professional work | Shipped asset collection and selected functional export checks | An exact source/output pair that passes both technical and creative checks in the intended workflow |
| Decide whether a feature is worth building | Bounded hypotheses and explicit next decisions | Observed creator tasks, actual correction effort and a recorded scale/iterate/stop decision |
| Hand a validated feature to engineering | Source references, control model and [handoff template](handoff-template.md) | An executed acceptance fixture, failure example and completed handoff; no shipped engineering adoption is claimed |

AI-assisted development and a packaged Skill are useful evidence, but neither establishes a reliable autonomous agent. Model-API orchestration, agent recovery and comparative creator research remain evidence to build, not labels to add to a screenshot.

## Review every new addition against the role

For each new film, interaction or case revision, ask what it proves: a production bottleneck, a design decision, automatic execution, creator authority, local recovery, delivery acceptance, or a validated next step. Link the evidence to that claim and mark what remains untested. A final film strengthens output evidence; it does not by itself prove usability, autonomy or reduced production time.

The new architectural outputs improve the presentation of Model Breakdown and Architecture Growth. The next iteration should expose one meaningful correction and its checks, rather than add a second gallery that repeats the same claim. Confidential work can demonstrate judgment through approved results and a high-level method without releasing its implementation.

## What to prove next

Prioritize **one complete Clockwork adaptation** and **one unassisted Collage session**. These extend the strongest existing evidence: production craft and an actual interface iteration. Record the brief, one local correction, the checked output and the decision it changes. Keep the same sources and quality target when comparing with an existing workflow.

For the remaining cases, use the bounded task at the top of each case page. Run a small exploratory study only after the core input-to-output path works. A few successful sessions justify the next experiment; they do not establish broad market demand or production reliability.

Use the [validation record](creator-validation.md) to capture observations. Expand when the core task succeeds at the agreed quality and corrections remain understandable. Iterate when the task matters but discovery, control or recovery fails. Stop or narrow an automation approach when it loses meaning, target identity, construction logic or takes more correction than the manual workflow.
